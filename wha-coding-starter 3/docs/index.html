Setting up
Here's the good news: the Claude Desktop app already includes Claude Code. There's no extra program to install, no "Node.js", no command line. You'll do everything through the app you've already got.
1

Open the Code tab

Where the building happens — about 60 seconds.

  1. Open the Claude Desktop app.
  2. Click the Code tab at the top centre of the window.
  3. Choose Local (this means "work with files on my own computer").
  4. Click Select folder — you'll pick your project in the next step.
If the Code tab ever asks you to upgrade, it just means that account needs a paid plan — yours is covered by the WHA Team account, so sign in and you're through.
2

Load your project & meet your team

A ready-made starter so you don't begin from a blank page.

  1. Download wha-starter.zip (sent alongside this guide) and double-click to unzip it.
  2. Move the wha-starter folder somewhere easy, like Documents. Rename it to your product's name if you like.
  3. Back in Claude → Code → Select folder → choose that folder.
  4. In the message box, type /agents and press enter to see your built-in helper team.
code-mentor ★
Your teacher. Reviews your work and explains the why. Lean on this constantly.
security-reviewer
Checks nothing unsafe slips through, especially with personal data.
supabase-migrator
Changes the database the safe, reversible way.
test-writer
Writes tests so future changes don't break things.
pr-prep
A pre-flight checklist before you publish a change.
domain-expert
Knows your product. Fill it in once you know what you're building.
The starter has a hidden folder named .claude that holds these helpers. You won't see it in Finder (hidden folders start with a dot) — that's completely normal. Claude finds it on its own.
3

Connect Supabase

This is your database and your sign-in system — where information lives.

Safety: those keys go into the project's .env.local file (Claude handles this for you). Never paste keys into a normal chat window or a random website — only into the project, when Claude asks.
House rule for later: changes to the database structure go through migrations (your supabase-migrator does this), never by editing tables directly in the Supabase website. It keeps everything reversible.
🔑 Where to find your Supabase keys

Claude needs two things from your Supabase project. Easiest way: click the green Connect button at the top of your Supabase dashboard — it shows both, ready to copy. To find them manually:

  1. Project URL — Settings (the ⚙️ gear, bottom-left) → API Keys. It looks like https://abcd1234.supabase.co
  2. Publishable key — same API Keys tab. It starts with sb_publishable_…  (if there isn't one yet, click Create new API keys).
Don't use the Secret key (sb_secret_…) when building — it's like a master password. The publishable key is the safe one for your app. If Claude ever needs the secret one, it'll put it somewhere private, never in your code.
4

Connect Vercel

This is where your work goes live on the internet — for when you're ready to share.

  1. Create your Vercel account and link it to your GitHub (Claude can walk you through making the GitHub repo).
  2. From then on, Vercel gives you a private preview link for every change, and publishes the real site when you're happy.
No rush on this one. You can build and try things on your own computer first — Vercel matters only when you want others to see it. Ask Claude: "I'm ready to publish — walk me through Vercel."
5

Your first build

Momentum beats perfection. Start tiny, on something you understand.

  1. Pick something small and familiar — e.g. "a simple page that lists our team and their roles."
  2. Type it to Claude in plain English. Let it build.
  3. Then type: "Use the code-mentor agent to review what you just built and explain it to me."
  4. Read the explanation. Ask follow-ups until it clicks. That loop is the whole job.
The rhythm: ask → let it build → have code-mentor review & explain → understand → save. Repeat. Every loop you understand a little more, and soon you're catching things yourself.

Five golden rules

The difference between "using AI" and actually learning to build.

1
Never keep code you can't explain. If you don't get it, say "explain this like I'm brand new" until you do.
2
One small change at a time. Small steps are easy to understand, easy to undo, hard to break.
3
Let code-mentor review everything. It's there to teach, not to judge. Use it on every change.
4
Save often. Commit your work in small chunks so you can always step back.
5
Stuck for 15 minutes? Ask. Paste the exact error to Claude, or message James. Being stuck is data, not failure.

Copy-paste cheat sheet

The exact phrases to type into the Code tab when you're not sure what to say.

To get oriented: What's in this project, and what does it do? To see your team: /agents To learn as you go: Use the code-mentor agent to explain this in plain English. To connect the database: Help me connect this project to my Supabase project. To build something: Build a simple page that … (describe it plainly) Before publishing: Use the pr-prep agent to check this is ready.
